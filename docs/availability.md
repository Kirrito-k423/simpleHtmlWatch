# 今日实验空闲窗口与全体汇总图

首页默认显示 NPU 状态，并打开“实验空闲窗口 · 全体汇总”。默认统计工作时段，可以切换非工作时段、全天或机器组。任务中台链接 `/?tasks=1` 仍直接进入任务页面；演示模式不自动打开真实统计。

## 五档窗口如何计算

统计每天北京时间 00:00 至当前已经出现的连续整机 NPU 空闲段。按每一段长度 `L` 分别累计 `floor(L / 档位长度)`，提供 **2 小时、1 小时、半小时、15 分钟、5 分钟** 五档。同一档内窗口互不重叠，不同档分别计算，不能把五档个数加在一起。

例如连续空闲 70 分钟，对应 0、1、2、4、14 个窗口；两个相隔未知或占用时间的 35 分钟空闲段，提供两个半小时窗口，但没有一小时窗口。空闲段起点可以是任意时刻，不要求对齐整点或 :00/:30。

只有完整有效 NPU 采样显示全部设备无进程、算力为零时才记录空闲；零算力但有进程仍计占用。沿用既有有时限前值估计，最长延续 `2 × 监控间隔 + 30 秒`；命令失败、未知进程表、断连及停机缺口中断连续性。记录精确到毫秒，不能发现两次采样之间的所有短进程。统计表示过去观测到的实验机会，不能保证未来独占，也不替代实时资源检查、任务授权和预约。

## 三种时间范围

每天均采用以下北京时间区间，含开始、不含结束，周末和节假日同样划分：

- `work` 工作时段：09:00–12:00、14:00–18:00、19:00–21:00，共 9 小时，默认展示。
- `off` 非工作时段：其余时间，共 15 小时。
- `all` 全天：00:00–24:00。

只统计当前已经过去的所选时间；未来时段不计入覆盖率分母。工作时段的午休与晚休边界会切断空闲段，不能跨越被排除的时间拼长窗口。非工作时段同理。全天允许同一空闲段跨过这些时刻，因此全天窗口个数未必等于两个分时段窗口个数之和。

v0.8.3 将原 NPU 利用率的工作时段汇总同步为 19:00–21:00；v0.8.2 的旧口径为 19:00–20:00。既有小时桶无需改写，查询使用当前时段定义。

## 领导总览图

每个已配置资源一条横条，按可用半小时窗个数从少到多排列。横轴单位为“30 分钟容量”，可以导出完整 **PNG 或 SVG**，明细表另可导出 CSV。

- 绿色：形成完整半小时窗口的空闲容量，绿色单位数是实际独立窗口个数。
- 黄色：每段切出完整窗口后剩余的碎片空闲。
- 红色：已观测占用时长。
- 灰色：未观测时长，不解释为占用或空闲。

每行严格满足：`半小时窗口个数 × 1800 秒 + 碎片空闲秒数 + 占用秒数 + 未观测秒数 = 已经过的所选时段秒数`。红、黄、灰表示时长折合单位，可以是小数，不是固定半小时格子的个数。覆盖率为已观测空闲与占用之和除以对应时段实际经过时长。

相同物理资源 ID 的入口只统计一份容量；有冲突的采样以占用优先。同一物理机器多个入口应配置相同 ID；没有物理标识的回环跳板不同端口分别显示为入口，无法保证排除重复，不能把未核实入口总数当成物理机器数。变更物理 ID、地址或型号时不沿用旧身份的连续空闲段。

## 数据与容量

复用现有 NPU 监控，不增加 SSH 命令。`occupancy/daily-windows.json.gz` 只保存当天合并后的空闲／占用／未知时间段及机器来源，不保存 PID、进程名、命令或原始采样。旧小时均值与五分钟桶无法还原精确连续段，**新功能从升级后积累，之前的当天时间明确显示未观测**。

只保留当前自然日，每分钟原子覆盖、正常退出保存，异常终止可能丢失最后不足一分钟。压缩文件最多 **256 KiB**，原子替换另需最多相同临时空间；内存最多 256 个来源、8,192 个时间段。超限先裁剪最早时间段，公开 `historyTruncated`，裁剪部分按未观测处理。记录损坏时保留原文件并报告错误，不因此阻断原有监控或任务受理。既有小时历史、六小时五分钟排序记录及存储验收基线保持各自原定义，不能将旧历史填成零来获得完整曲线。

## 只读接口与 AI 客户端

能力：`daily-idle-windows-v1`。连接前先 discover 核对实例与能力；缺少能力不能触发自动升级或重启。

```sh
python3 skills/simplehtmlwatch-netdata/scripts/metricsctl.py --instance <实例名> availability
python3 skills/simplehtmlwatch-netdata/scripts/metricsctl.py --instance <实例名> availability --scope off
python3 skills/simplehtmlwatch-netdata/scripts/metricsctl.py --instance <实例名> availability --scope all --group "A5 B01"
```

`GET /api/availability?scope=work|off|all&group=...`，默认 `work`。只允许 GET 和单值 `scope`／`group` 参数，使用既有会话鉴权及实例 fencing；查询不联系 SSH、不写文件、不主动补齐未结束的采样间隔。

响应包含当前时段、北京时间起止时间、每资源与全体的 `counts`（`minutes5/15/30/60/120`）、空闲／占用／未知／碎片秒数、最长空闲段、覆盖率和历史存储状态。`expectedSeconds` 为每资源已经过去的所选时段秒数。客户端 `complete` 要求有机器、覆盖率 100%、无保存错误及容量裁剪；退出码 3 表示数据不全，有效部分仍可报告。缺失历史中的零个窗口不能表述为“全天没有空闲机会”。

升级沿用内置有界备份；新记录位于已纳入备份的 `occupancy/`，不改写旧小时桶或六小时排序格式。实际部署核对唯一实例、数据目录、程序及端口，任务恢复仍只查询原任务 ID，不重放命令。
