# 历史记录与关联回放：界面原型

这是 throwaway 原型，保存在 `codex/prototype-watch-history`，不属于正式版。它要回答的问题是：能否从历史 NPU 占用，沿着同轮 PID 找到当时的进程命令和工作目录？

## 一条命令运行

在本分支的仓库根目录运行（需要 Python 3，仅用于查看原型）：

```sh
python3 scripts/run-history-prototype.py
```

打开 http://127.0.0.1:19877/?demo=1&prototype=history&variant=A 。可在命令末尾指定其它端口。正式 Windows 程序的打包方式不受影响。

底部左右箭头切换三种布局，URL 的 `variant` 分别为 `A`、`B`、`C`；非输入控件焦点下也可用键盘左右键切换。现有首页是原型宿主，仅专用启动器注入开启标记，普通程序不启用此界面。

| 方案 | 主要入口 | 适用问题 |
| --- | --- | --- |
| A 时间轴与双栏证据 | 选机器、点时间片；NPU 与 ps 并排 | 已经知道大概时刻，逐帧查看发生了什么 |
| B 疑似竞争事件列表 | 按事件进入，查看事件前一帧 | 快速找到同卡新出现的任务，再核对命令和目录 |
| C 多机时间矩阵 | 点击机器与时间交叉格 | 先浏览整批机器的历史，再下钻单次采样 |

## 可操作范围

- 16 台模拟机器、24 轮初始记录、4 秒采样间隔，共 384 份机器快照。
- 开始/停止模拟记录：每 4 秒追加一轮到浏览器内存。使用连续的模拟时钟，不是真实墙钟。
- 回放暂停、逐帧、1/2/4 倍速、时间轴、跟随最新。记录可以继续，手动选择旧帧不会被新增记录拉回最新。
- 同轮原始 NPU 输出、ps 输出、PID → 工作目录表；点击 PID 联动选中的任务。
- 采集缺失用问号和缺失提示，目录未取得单独提示，不用当前状态或上一帧伪造历史。
- 展开“查看原型状态 / 数据模型”查看相关状态，切换布局保持机器、时刻与 PID。

所有机器、PID、目录和输出均为生成的模拟数据；不连接 SSH、不读取真实凭据、不保存历史，刷新重置。演示仅包含 NPU 0，未验证真实型号的 npu-smi 输出解析，也没有生产记录接口。

## 快速体验

1. A 默认 ascend-01 / 14:00:40。同卡 PID 4101 与 7702 对应不同工作目录，点击两者看联动。
2. 14:01:00 的 PID 7702 在读取 cwd 前退出：保留 NPU/ps 观察，目录显示未取得；下一帧不再出现该 PID。
3. B 选择 ascend-04 的事件，再点“看事件前一帧”：从两个 PID 回到一个 PID。
4. C 点击 ascend-02 / 14:00:44：显示整帧采集缺失，不能解释成没有任务。
5. 停在旧帧后开始模拟记录，等待超过 4 秒：快照计数增加，选中时刻不变。点击“跟随最新”才跟随新记录。

## 目前结论与验证边界

浏览器中已经验证三种布局切换、事件前一帧、PID 目录联动、整帧缺失、cwd 缺失、4 倍速回放到末帧，以及模拟记录增长而旧帧保持。已观察到 384 → 512 份快照增长，选中时刻保持在 14:00:44；桌面 1440×1000 与窄窗口均查看过。JS 语法检查通过。

设计建议是 B 的事件入口结合 A 的证据对照，C 作为总览。**这是待用户选择的设计建议，尚未选定最终界面，也不是正式采集功能的验证。** 原型代码只作为需求与交互的第一手材料，不直接合入 main。

## 正式实现需要保留的证据

一次机器采样应保存机器稳定 ID、sample ID、采样起止时间，以及各命令自己的采集时间/错误；绑定原始 `npu-smi info`、完整 `ps -ef`、涉及 PID 的 `/proc/<pid>/cwd`。不要只保留筛选 Python 后的进程列表。

`ps -ef` 本身通常没有工作目录，所以 cwd 必须在采样时额外取得并存档。PID 会复用，关联还需机器 boot ID 与进程 starttime，并检查采集过程中的身份变化；原型展示这些字段，但没有实现真实采集校验。多条命令不是原子快照，应保留它们的时间跨度。进程提前退出、权限问题和断线必须保留缺失，不能回放时再查当前机器补齐。

同卡多 PID 只说明疑似竞争，合法协同任务也可能有多个进程。目录和命令帮助定位任务；大家共用 root 时不能仅据此确定具体人员。真实落地还需验证设备输出中的 PID、容器 PID/目录命名空间，以及采样间隔内短任务漏采的情况。

生产阶段另行实现本地持久化、记录范围、容量/保留期限、历史查询与重启后回放，评估全量 ps/cwd 采集成本和真实 SSH 结果。当前没有实现这些能力。
