# 今日实验空闲窗口与全体汇总图

首页默认显示 NPU 状态，并打开“实验空闲窗口 · 全体汇总”。默认统计工作时段，可以切换非工作时段、全天或机器组。v0.8.6 增加日期选择：今天加过去7个北京时间自然日，共8个日期。任务中台链接 `/?tasks=1` 仍直接进入任务页面；演示模式不自动打开真实统计。

## 五档窗口如何计算

统计每天北京时间 00:00 至当前已经出现的连续整机 NPU 空闲段。按每一段长度 `L` 分别累计 `floor(L / 档位长度)`，提供 **2 小时、1 小时、半小时、15 分钟、5 分钟** 五档。同一档内窗口互不重叠，不同档分别计算，不能把五档个数加在一起。

例如连续空闲 70 分钟，对应 0、1、2、4、14 个窗口；两个相隔未知或占用时间的 35 分钟空闲段，提供两个半小时窗口，但没有一小时窗口。空闲段起点可以是任意时刻，不要求对齐整点或 :00/:30。

只有完整有效 NPU 采样显示全部设备无进程、算力为零时才记录空闲；零算力但有进程仍计占用。沿用既有有时限前值估计，最长延续 `2 × 监控间隔 + 30 秒`；命令失败、未知进程表、断连及停机缺口中断连续性。记录精确到毫秒，不能发现两次采样之间的所有短进程。统计表示过去观测到的实验机会，不能保证未来独占，也不替代实时资源检查、任务授权和预约。

## 三种时间范围

每天均采用以下北京时间区间，含开始、不含结束，周末和节假日同样划分：

- `work` 工作时段：09:00–12:00、14:00–18:00、19:00–21:00，共 9 小时，默认展示。
- `off` 非工作时段：其余时间，共 15 小时。
- `all` 全天：00:00–24:00。

只统计当前已经过去的所选时间；未来时段不计入覆盖率分母。工作时段的午休与晚休边界会切断空闲段，不能跨越被排除的时间拼长窗口。非工作时段同理。全天允许同一空闲段跨过这些时刻，因此全天窗口个数未必等于两个分时段窗口个数之和。

v0.8.3 将原 NPU 利用率的工作时段汇总同步为 19:00–21:00；v0.8.2 的旧口径为 19:00–20:00。既有小时桶无需改写，查询使用当前时段定义。

## 全屏五图与圆环方格

v0.8.4 将总览铺满浏览器页面，五个时间档位各有一张图，全部并排展示。每图均显示全部节点，每节点一个方形格子及圆环；根据视口宽高自动安排格子，五图节点顺序相同，无需翻页或滚动长条图。短名称显示在格子顶部，完整名称和身份从悬停或点击明细读取。PNG／SVG 导出包含全部五图，CSV 保留五档计数。

每个时间档位分别将对应窗口所占空闲容量标为绿色，剩余零散空闲为黄色，已观测占用为红色，未观测为灰色。节点圆环满足 `该档次数 × 档位秒数 + 剩余空闲秒数 + 占用秒数 + 未观测秒数 = 已经过的所选时段秒数`。未知不解释为占用或空闲。

v0.8.5 图头显示 `独立空闲窗 实际数 / 理论上限 个` 或 `可排布 实际数 / 理论上限 次`，PNG／SVG 及 CSV 同步包含上限。v0.8.6 同时显示实际数占理论上限的百分比，例如 `36 / 295 个 · 12.2%`；分母为0时显示 `—`，不显示0%或无限大。这个比例是空闲实验机会比例，不是 NPU 算力利用率。分母假设当天截至当前，所选范围内全部合格节点始终空闲；未知时间也计入理论容量，但不增加实际空闲数。每个连续所选时段分别计算 `floor(时段长度 / 档位长度)`，不能拼接午休等间隔；不包含今天尚未经过的时段。单机乘以去重后的节点数，多机乘以各合格 B 组 `floor(可确认成员数 / 组网规模)` 之和；身份不明、历史组别不符、超8节点等已排除成员／组不贡献多机上限。例如 21:00 时非工作已过 9+2+1 小时，单节点2小时档上限为 4+1+0=5，而非6。分母是全空闲假设的容量，不是当前实际空闲历史的最优排布。

## 同组双机、四机和8机

组网规模选择作用于全部五图，默认单机。多机要求固定的同一批物理节点在完整窗口内连续同时空闲，并且属于明确的同一个 B 组。B组只读取配置中的分组，不从 IP 或名字中的“跳板”推断，因此 B04 经 B05 转发的入口仍按实际配置归属处理。不同 B 组不组合；整个过程中空闲节点数始终够用但搭档中途变化，也不能拼成长窗口。

沿用“独立机会”口径：8 台同时空闲半小时，双机计 4 次、四机 2 次、8机 1 次，不把 28 种重叠配对相加。同一时间档位的一份排布中，同一物理节点不能同时参与两个实验；五个时长仍各自独立计算。

算法返回一组**保守可行排布，不宣称全局最大值**。先对同组固定成员的完整空闲段求交集，再按最早可完成时间安排；相同时刻优先使用最早结束的共同空闲段，最后按资源身份稳定排序。每次分配后更新所有成员的可用起点。不同 B 组分别排布，再合计实验次数。

图头是独立实验次数；多机模式下节点圆环中心是该节点参与次数，不能直接把节点中心数字相加当成实验次数：`全部参与次数 = 每次节点数 × 独立实验次数`。黄色还包括本次可行排布未使用的空闲，并不保证这些时间能形成另一份组网机会。

点击节点可核对固定成员、B组和北京时间起止。相邻同成员的窗口合并成重复次数，最多每个时间档位返回256段明细；另有省略数量时明确提示，计数仍覆盖完整排布。物理入口依原资源ID去重；未标识回环跳板、B组归属不明／矛盾、同组超过8个节点时不能猜测组网。若当天记录的B组与当前配置不同，不能把旧组历史借到新组，单机历史仍保留，待下一自然日重新记录明确归属。

## 数据与容量

复用现有 NPU 监控，不增加 SSH 命令。`occupancy/daily-windows.json.gz` 保存当天合并后的空闲／占用／未知时间段及机器来源；已结束日期保存到 `occupancy/window-history/YYYY-MM-DD.json.gz`。不保存 PID、进程名、命令、凭据或原始采样。v0.8.6 保留今天加过去7天，复用当天已有记录；旧版本已经丢弃的过去日期无法由小时均值或五分钟桶还原，日期列表明确标记“无历史”，不估算填充。

每分钟原子保存、正常退出保存，异常终止可能丢失最后不足一分钟。跨午夜的有界观测会分别写入前一天与当天，不拼接成跨日窗口；重启时迁移仍在旧当天文件中的上一日，不丢弃它。每个日期最多 **256 KiB** 压缩文件、256个来源及8,192个时间段，总共最多8份日记录（2 MiB），原子替换另需最多256 KiB。过去日期保留当天最后配置的无凭据节点／物理身份／分组清单，不借用今天变更后的节点或组别；旧文件没有清单时只采用其已记录身份。超过7天的专属日文件在保存时自动清理。超限先裁剪最早时间段，公开 `historyTruncated`，裁剪部分按未观测处理。记录损坏时保留原文件并报告错误，不因此阻断原有监控或任务受理。既有小时历史、六小时五分钟排序记录及存储验收基线保持各自原定义，不能将旧历史填成零来获得完整曲线。

## 只读接口与 AI 客户端

单机能力：`daily-idle-windows-v1`；多机额外要求 `simultaneous-idle-windows-v1`；历史日期要求 `weekly-idle-windows-v1`。连接前先 discover 核对实例与能力；缺少能力不能触发自动升级或重启。

```sh
python3 skills/simplehtmlwatch-netdata/scripts/metricsctl.py --instance <实例名> availability
python3 skills/simplehtmlwatch-netdata/scripts/metricsctl.py --instance <实例名> availability --scope off
python3 skills/simplehtmlwatch-netdata/scripts/metricsctl.py --instance <实例名> availability --scope all --group "A5 B01" --nodes 4
```

`GET /api/availability?scope=work|off|all&group=...&nodes=1|2|4|8&date=YYYY-MM-DD`，默认 `work` 与单机。可选 `date` 默认为今天，只接受今天及过去7天；历史日期按完整自然日计算。只允许 GET 和单值 `scope`／`group`／`nodes`／`date` 参数，使用既有会话鉴权及实例 fencing；查询不联系 SSH、不写文件、不主动补齐未结束的采样间隔。

响应包含当前时段、北京时间起止时间、每资源与全体的 `counts`（`minutes5/15/30/60/120`）、空闲／占用／未知／碎片秒数、最长空闲段、覆盖率和历史存储状态。`expectedSeconds` 为每资源已经过去的所选时段秒数。客户端 `complete` 要求有机器、覆盖率 100%、无保存错误及容量裁剪；退出码 3 表示数据不全，有效部分仍可报告。缺失历史中的零个窗口不能表述为“全天没有空闲机会”。

v0.8.5 额外返回全体 `theoreticalCounts`，五档键与 `counts` 一致，表示上述全空闲理论上限。该字段为兼容性新增，不改写任何历史文件。

多机响应新增 `nodes`、`countPolicy`、`pools`、`plans` 和 `omittedPlans`。多机 `counts` 表示独立实验数，每节点 `counts` 表示参与次数；身份或分组不明确时通过 `multiReason` 明示排除，客户端不能宣称完整。默认单机仍为原来的精确连续段切分计数。

升级沿用内置有界备份；新记录位于已纳入备份的 `occupancy/`，不改写旧小时桶或六小时排序格式。实际部署核对唯一实例、数据目录、程序及端口，任务恢复仍只查询原任务 ID，不重放命令。

v0.8.6 新增 `capacityPercent`（五档百分比数值，零分母为 null）、`date`、`today`、`dates`（8个日期及可用／异常状态）、`groups` 和 `historyAvailable`。未保留的历史返回 `historyAvailable:false`、空节点和 null 比例，页面显示无历史数据；不能将其解释为零个真实机会。单个历史日损坏单独报告并保留原文件，不阻断当天采集；日期查询不写文件。包内客户端支持 `availability --date YYYY-MM-DD`，严格核验服务返回的是所选日期。
