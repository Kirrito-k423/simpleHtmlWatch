# 机器级 NPU 利用率历史

在页面点击“NPU 利用率”，查询今天、昨天或近 7 个完整自然日。所有小时按北京时间（Asia/Shanghai，UTC+8）划分。“昨天”是昨日 00:00 至今日 00:00；“近 7 个完整日”不包含今天。跨机器表格显示每小时均值；一周视图可看各日期，或比较一周同一小时的规律。点击机器查看均值、峰值、低负载占比、覆盖率与采样数；CSV 导出保留这些字段。

## 采集与统计

- 服务运行且机器启用 NPU 监控时，复用已有的 `npu-smi info` 结果；不额外执行 SSH 命令，不依赖 Netdata，也不需要开启文本历史记录。浏览器关闭后继续采集；本机中台停止期间没有数据。
- 识别 A2/A3 风格的 `AICore(%)` 与 A5 风格的 `NPU Util(%)` 表头。先对同轮全部可识别 NPU／芯片行求平均，再进入机器级统计；不保存或返回单卡数值。不同型号、指标或 SSH 地址分别保留，避免混合口径。暂不支持 NVIDIA GPU。
- 只接受退出码为 0、无错误／警告、未截断且利用率表完整的输出。N/A、异常范围、未识别格式及部分卡缺失都视为本轮缺失，不用剩余行凑平均。驱动新增格式需先验证解析。
- 小时均值按有效观测时长加权。相邻采样间用前值估计；最多延续 `2 × 配置采样间隔 + 30 秒`，后续缺口不补值。采样失败时中断延续；重启不恢复未完成的采样间隔。峰值是整机均值的采样峰值，不是单卡峰值。
- 低负载占比是已观测时长中，整机均值**低于 10%**的比例。覆盖率是已观测时长／请求时段的实际经过时长。当前小时尚未结束，未来小时没有数值。仅有一份样本且尚无有效间隔时均值仍为 null。
- 候选低谷需要完整小时覆盖率至少 90%，且其中至少 90% 已观测时长的整机均值低于 10%；合并连续合格小时。整机平均值会隐藏卡间差异，候选时段不证明当前每张卡空闲、HBM 足够、无其他进程或任务占用。提交前通过任务中台核对当前资源。

## 紧凑存储与容量

独立目录 `utilization/` 每天一个原子覆盖保存的 JSON 文件；日期和机器元数据各保存一次，每机器的小时桶用固定六元素整数数组保存：

```text
[小时, 有效毫秒数, 利用率百分比×100×毫秒的累计值, 低于10%的毫秒数, 峰值百分比×100, 有效采样数]
```

没有逐次采样、单卡明细、命令正文、进程信息或 SSH 凭据。内存实时更新，最多每分钟保存一次，正常退出前保存；异常掉电／崩溃可能损失最后不足一分钟尚未落盘的统计。原子覆盖期间也为临时文件预留容量。

保留包含今天在内的最近 30 个自然日，总上限 **20 MiB**；首先淘汰过期日期，仍超过限制则淘汰最早日期。单日日文件最多 2 MiB，超限／写失败会显示存储错误，实时监控继续。容量限制可能使历史不足 30 天。此上限只包含利用率目录，原有文本历史和任务归档独立。

合成容量测试：60 台机器 × 30 天 × 24 个完整小时桶，共 43,200 条，JSON 实际约 2.06 MiB。此结果是格式容量验证，不是历史负载实测。页面与 API 返回实际落盘用量。未曾采集的历史日期无法补回。

## AI 只读查询

读取 `simplehtmlwatch-netdata` Skill，用同一实例先 discover。机器级利用率接口要求独立能力 `accelerator-utilization-v1`，不要求 Netdata Agent：

```sh
python3 "$SKILL_DIR/scripts/metricsctl.py" --instance <实例名> discover
python3 "$SKILL_DIR/scripts/metricsctl.py" --instance <实例名> utilization --period yesterday
python3 "$SKILL_DIR/scripts/metricsctl.py" --instance <实例名> utilization --period week --group <机器组>
python3 "$SKILL_DIR/scripts/metricsctl.py" --instance <实例名> utilization --date 2026-10-08 --days 1 --machine <机器ID>
```

查询 API：`GET /api/utilization?period=today|yesterday|week`，或 `GET /api/utilization?date=YYYY-MM-DD&days=1`。可附 `machineId`、`group`。遵守现有会话令牌、runId 和实例发现规则；仅 GET，查询不连接远端。查询日期须位于保留的 30 个自然日内；已淘汰／缺失历史仍明确返回 null。

响应为每机器 `hours`、一周同小时聚合 `hourOfDay`、`lowWindows`，并包含型号、厂商指标口径、时间范围、存储状态。窗口均值按全部有效时长加权，同小时跨日聚合也按有效时长加权。机器改地址或型号时会分成不同统计行，报告时保留来源，不自行把同名行加在一起。

客户端退出码 0 表示所有返回机器窗口均值有效、覆盖率至少 90% 且无存储错误；3 表示数据不全／没有数据／存储错误；2 表示参数、身份或请求失败。退出码 3 的有效数据仍可使用，但不能宣称完整历史。启动初期查询昨天或一周通常是 3，这是历史尚未积累的正常结果，不应重启或换版本。
