# 升级备份、外置归档与恢复

v0.8.1 的 `upgrade-backup-archive-v1` 在维护者显式 `-adopt-build` 且构建实际改变时，先保存旧程序及核心状态，校验通过才加载新版数据。在线实例仍只复用；查询失败不能触发升级。

## 自动策略

- 本机 `rollback/last.shwb` 固定一份升级前快照，`rollback/current-program` 固定缓存当前程序，防止同路径覆盖后丢失旧构建。缓存最多64 MiB，单份加密压缩归档最多128 MiB、展开内容最多512 MiB。超限拒绝升级，保留原状态。
- 快照包含旧程序、`config.enc`、`vault.key`、`known_hosts.json`、`service.json`、备份策略，以及 `tasks/`、`utilization/`、`occupancy/`、`exports/` 内的 JSON/gzip JSON。包含完成索引、预约、等待单和清理状态；排除结果包、远端程序、诊断文本和锁文件。结果包留在原位置。
- 启动及每30分钟重试归档同一快照，不生成新的采样日志。外置升级快照最多3份，超过30天淘汰，但始终保护最近2份经摘要和解密验证的快照。最新两份无法验证时停止清理。
- 外置路径与仓库标识持久化。失联或标识改变时不重建挂载路径、不删除本机回滚文件；错误写入固定的 `backup-status.json`，重连后自动重试。离线期间继续授权升级，本机仍仅保留最近一次快照，更早未归档代可能被替换。
- 独立备份锁保护维护操作，仅清理专属工作区中的中断临时文件。历史手工资料 `legacy-*.shwb` 不参加升级快照自动淘汰；不同解密钥匙的备份互不清理。

首次配置示例，路径的父目录须已存在，替换准确实例和目录：

```sh
./simpleHtmlWatch -instance <实例名> -data-dir "<数据目录>" -adopt-build \
  -backup-archive-dir "/已挂载外置盘/已有父目录/simpleHtmlWatch-backups" -no-browser
./simpleHtmlWatch -instance <实例名> -data-dir "<数据目录>" -backup-status
```

以后启动无需重复外置参数。从没有缓存的旧版首次升级时，保留旧程序原路径，从新版解压目录运行；不要先覆盖旧二进制。找不到与旧登记 SHA-256 匹配的程序时拒绝采用新构建。

## 加密和验证

归档先 ZIP 压缩，再用标准库 AES-256-GCM 认证加密。内部清单含逐文件 SHA-256、大小、权限和修改时间。每次归档解密核验；删除旧来源前，在本机受限临时目录实际恢复全部文件，并两次核对源树和外置副本。变化或失败时保留原件，拒绝符号链接和特殊文件。

解密钥匙是实例目录的 **`backup-archive.key`**，32字节，macOS/Linux 权限0600。归档和公开收据不包含钥匙。请另存到安全的密码库或加密备份；仅有外置 `.shwb` 无法恢复。不要把钥匙明文放到同一 exFAT 盘、发给外部AI或打进发布包。

## 历史资料归档

仅对已授权的静态旧备份目录使用；活动实例及核心状态目录会被拒绝。来源须是指定根目录的直接实际子目录，命令不启动服务或 SSH。

```sh
./simpleHtmlWatch -data-dir "<保存钥匙的实例目录>" \
  -archive-backup "<旧备份父目录>/<指定旧备份>" -backup-source-root "<旧备份父目录>" \
  -backup-archive-dir "<外置归档仓库>" -remove-archived-source
```

不加删除参数则保留原件，仍执行实际恢复演练。来源未变时可用相同参数继续中断的归档，不覆盖其他来源的同名文件。收据仅含路径、摘要、文件数和字节数。

## 恢复与回滚

```sh
./simpleHtmlWatch -data-dir "<保存钥匙的实例目录>" -verify-backup "<备份.shwb>"
./simpleHtmlWatch -data-dir "<保存钥匙的实例目录>" \
  -restore-backup "<备份.shwb>" -restore-dir "<必须不存在的恢复目录>"
```

恢复只写新目录，不覆盖当前实例。升级快照展开为 `runtime/simpleHtmlWatch`（Windows 运行前可改名 `.exe`）和 `data/`；历史资料按原结构恢复。保留文件内容、基本权限、修改时间和空目录，不保存ACL、扩展属性或创建时间。

实际回滚由唯一维护者核对任务、远端状态、数据格式和准确进程后安排。不能直接让旧程序读取新版状态，旧预约也不是当前资源授权。快照的登记含原正式路径，在临时恢复目录直接启动会因路径不符被拒绝。若决定原位回滚，先保全当前状态，再恢复对应程序及核心数据到原路径，保留锁文件和其他原结果文件。重新发现后只查询原任务ID，不重放远端命令。此过程结合实际任务判断，不自动执行回滚。
