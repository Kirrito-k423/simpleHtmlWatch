v0.7.1 修复元数据空间预算耗尽后拒绝新任务的问题。较老已完成任务的详情自动清理，空间目标满额也不再返回 HTTP 507 STORAGE_BUDGET_FULL。

- 通常保留最近 100 条可清理的完整任务详情，超出元数据软目标时缩到 20 条。只处理已确认退出的 succeeded/failed，保留运行中、unknown、有效预约及未结束实验的依赖。
- 清理前先持久化 gzip 状态/去重索引，随后移除旧 job.json；原 ID、请求摘要、退出码和结果下载定位保留。相同请求查询原记录，不重复启动；不同请求复用旧 ID 仍冲突。
- 所有已有结果包继续保留、可下载。较早命令和事件详情标为 historyCompacted，网页说明已清理。
- 清理失败或受保护记录较多时仍允许新任务，storage 提供软目标、压缩计数和清理错误。参数、认证、资源互斥及实际持久化失败仍正常报错。
- 兼容既有版本 1/2 的计量文件与明确扩容值，不重置原基线。新增 completed-task-retention-v1；维护备份须包含 completed.json.gz，采用后不能直接降级旧程序。

30 天尽量新增不超过 5 MB 的目标继续实际观测；任务可用性与活动证据优先，不能用拒绝任务保证空间指标。
