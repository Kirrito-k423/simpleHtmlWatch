v0.8.0 新增五档空闲机器排序、最近 6 小时的 5 分钟占用统计和当前资源检查，供预计使用不超过一小时的任务选择候选。

- 启动及北京时间整点、半点原子更新 `exports/idle-ranking.json`；页面顶部“空闲机器排序”显示历史偏好、覆盖率、当前占用与 HBM，并可筛选和下载 JSON。
- 默认实时门槛为无 NPU 进程、算力为 0、每设备至少 1024 MB 空闲 HBM、采样足够新鲜且无中台任务/预约/等待单占用；AI 可按实际任务指定型号、设备数、HBM 和采样年龄。
- 新增 `idle-machine-ranking-v1` 和两个 Python 客户端的 `idle-ranking` 子命令。查询只读，实际使用前仍须重新检查并走原预约/提交协议。
- 细粒度历史压缩文件最多 64 KiB，自动 JSON 最多 128 KiB，保留缺失和独立错误状态，不增加 SSH 轮询。

升级保留原实例身份、端口、配置、小时历史、任务、预约、等待单及清理策略。5 分钟历史从升级后积累，旧小时数据不能补回；开始时“历史不足”是正常状态。原 `ready` 与不指定机器的提交规则继续遵循原定义。维护前核对准确实例和进程，备份原构建及状态，正常停止后使用 `-adopt-build` 选择新构建。详见 [使用说明](../idle-ranking.md) 与 [生命周期](../service-lifecycle.md)。
