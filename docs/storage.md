# 本机空间预算与结果下载

目标是中台持续运行 30 天，新增常驻数据尽量控制在 **5 MB（5,000,000 字节）**。自 v0.7.1 起，任务可用性优先：空间目标不能作为拒绝新任务的理由，满额也不返回 `HTTP 507 STORAGE_BUDGET_FULL`。这不是可执行程序体积，也不包含用户主动下载的实验产物、手工备份、独立 Netdata Agent 的数据库和日志。后几项需要单独管理，不能声称它们也受中台预算限制。

## 为什么需要总量预算

旧设计会在每个任务结束后自动回收完整 stdout、stderr 和 results，单包允许 10 GiB，但没有全局总量或过期策略。即使单次任务不大，长期运行也会积累大量结果包；安装资源、独立 Agent 数据库、人工备份及每任务的小文件分配开销还会叠加。只清理一次缓存不能解决再次增长。

## 新的持久化策略

| 数据 | 策略 |
| --- | --- |
| 完整监控输出、ps、进程目录历史 | 移除采集、持久化和回放入口，旧 API 返回 410；不删除旧文件 |
| 任务结果 | 退出时仅记录状态和退出码。下载时远端 tar → SSH → HTTP → 用户指定文件；服务目录没有第二份缓存 |
| 已有结果缓存 | 优先读取原缓存，保持历史结果可下载；文件缺失时尝试读取远端原任务，不重跑命令 |
| 任务状态、预约、等待单、诊断 | 默认 **2,000,000 字节新增目标**，属于软目标；按 4 KiB 单元和任务目录计费。写入不因目标满额失败 |
| 已完成任务详情 | 通常保留最近 100 条可清理的完整详情；超出元数据目标时缩到最近 20 条，按完成时间先旧后新清理。状态、退出码、原请求摘要和下载定位压缩保存到 `completed.json.gz` |
| 每任务事件 | 首条及最近 31 条；超出计入 eventsDropped；新事件文本最多约 1 KiB |
| 清理诊断 | 额外设 512 KiB 上限；满额停止诊断写入和终止操作，保留已有证据。旧目录已超限时也不会自动删除证据 |
| 明确选择的服务诊断日志 | 维护者用 `-bounded-log` 逐个指定数据目录内的 `.log`；最多 8 个，每 30 秒检查，超过 64 KiB 时原位保留末尾 32 KiB，不中断现有写入进程 |
| NPU 小时汇总 | 最多 30 个自然日，gzip 日文件和原子替换临时文件共受 **2,000,000 字节**限制；按最早日期淘汰 |

任务计量第一次启动时记录已有元数据基线，固化在 `tasks/storage-budget.json`，后续启动不重置。兼容旧版本 1 的默认 2 MB 及受控维护版本 2 的扩容记录；已有 8 MB 等明确设置继续保留，改为软目标。配置损坏仍报错，不能通过删除计量文件规避调查。

启动、受理新任务前和每分钟都会检查较老的已完成任务。仅清理有明确结束时间和退出码的 succeeded/failed 任务详情，保留最近 100 条；超过目标时保留 20 条。运行中、发送中、unknown、人工解除但退出码未知的任务不清理，有未释放预约或未结束实验等待单引用的任务也不清理。

清理先原子写入压缩状态与去重索引，并确认目录持久化，再删除旧 `job.json`；不递归删除任务目录，也不删除已有 `result.tar.gz`。命令正文、详细状态事件及较早错误文本被移除，查询会带 `historyCompacted: true`。原 ID、请求 SHA-256、状态、退出码、机器及下载定位保留。相同 ID 和相同请求查询原记录；相同 ID 携带不同请求仍返回冲突，不能以清理为理由重跑旧实验。重启时压缩索引与原子清理中断后留下的重复文件会核对请求身份。

可清理记录不足或清理失败时仍允许新任务继续写入，`storage` 返回 `retentionError` 和 `overTargetBytes`，不以软预算拒绝任务、预约或实验状态更新。实际文件系统写入失败仍不能安全启动远端任务，认证、参数和资源互斥校验也继续有效。保留活动证据和永久去重所需的少量索引可能超过空间目标，因此 5 MB 是尽量达到的观测目标，不能以拒绝工作或删除未知占用实现。

默认元数据软目标与利用率上限合计约 4 MB，余量用于配置、目录及分配差异。外部启动器和 SSH 转发的日志不自动受预算约束；维护者可明确加入最多 8 个诊断日志，检查后的合计上限为 512 KiB。它们不能是实验输出，首次启用前可把原诊断日志备份到被测目录之外；截取瞬间并发写入的少量诊断行可能丢失。此功能不重命名文件或重启写入进程，30 秒检查间隙仍可能短暂超过阈值。元数据原子替换存在瞬时临时文件；异常中断、第三方进程、人工复制和用户下载不在常驻增量保证内。请结合实际目录占用验收，不能把合成测试写成真实运行 30 天。

## 客户端与升级

发现能力包括 `task-result-stream-v1`、`bounded-storage-v1`，v0.7.1 新增 `completed-task-retention-v1`。任务响应新增 `archiveMode: "remote"`，`archiveReady` 仅表示历史本机缓存；新版 `wait` 看到已确认远端结束就返回，随后主动 `download` 并核验产物。旧版客户端会等待 archiveReady，因此须同步更新包内 Skill。`collect` 返回 410，不再生成本机缓存。

```sh
python3 skills/cluster-task-controller/scripts/taskctl.py --instance <实例名> storage
python3 skills/cluster-task-controller/scripts/taskctl.py --instance <实例名> wait <原任务ID>
python3 skills/cluster-task-controller/scripts/taskctl.py --instance <实例名> download <原任务ID> --out /绝对路径/result.tar.gz
```

`GET /api/tasks/storage` 返回基线、当前计量、软目标和状态预留，并提供 `policy: "prune-completed"`、`admissionBlocked: false`、`compactedTasks`、`detailedTasks`、`overTargetBytes` 和 `retentionError`。只有历史本机缓存支持 HTTP Range；远端即时生成的压缩流不支持续传。下载中断就删除客户端残件并重新下载；不重新运行实验。远端原文件被删除或机器不可连接时无法重新生成结果。

小时日文件从 `.json` 改为 `.json.gz`，新版仍读取旧六字段和八字段 JSON；旧日文件在后续实际更新时才转换，成功写入压缩文件后才删除同日旧 JSON。旧构建不能读取压缩文件，也不遵守预算，不得直接降级。实验 complete 仍要求远端退出码和调用方提交的实验依据；取消对本机 archiveReady 的依赖，不代表无需下载、检查实验结果。

升级遵循 [实例维护流程](service-lifecycle.md)，先核对实例、进程及活动任务，不自动替换在线服务。测试实例必须为空，不能复制正式凭据或任务。

## 既有大文件的处置边界

- 删除离线安装包不影响已安装 Agent 的查询；后续离线安装需要重新获取安装包。
- 删除任务结果缓存不影响任务状态、时间线、调度或预约，但完整日志、性能数据及报告可能只有这一份；确认其他副本之前保留。
- 本机预览 Netdata 是独立 launchd 服务，仍会写数据库和日志。要约束整个目录的增长，维护者须另行停用本机预览或管理它的存储，不能仅靠升级中台。
- 不删除 `vault.key`、`config.enc`、主机指纹、`service.json`、`app.lock`、任务身份、预约或等待单来释放空间。

## 验证边界

测试覆盖旧计量版本兼容、满额继续接收任务、历史详情清理及重启去重、保留已有结果下载、活动证据保护、清理失败不阻断受理、下载不产生本机缓存、传输中断以及旧 JSON 与 gzip 兼容。60 台机器 × 30 天 × 24 小时、每小时不同统计值的合成文件共约 0.64 MiB；按 4 KiB 分配并加上 2 MB 元数据增长预算和 0.5 MB 余量，估算约 3.24 MB。这不是实际运行 30 天的测量。

本机运行验收、跨平台编译、各平台实际运行测试和真实部署验收需分别报告。升级后应记录数据目录的真实占用基线，并持续观察 30 天，不能以合成数据替代长期运行结论。

## 真实 30 天增量验收

发布包附带只读扫描脚本 `scripts/storage_audit.py`。状态文件必须放到被测目录之外，基线只能创建一次；每天的采样记录会合并为一条，最多保留 35 条，状态文件最多 128 KiB。它不会清理文件、修改配置、连接远端机器或重启服务。

```sh
python3 scripts/storage_audit.py --root /实际用户配置目录/simpleHtmlWatch --state /独立维护目录/storage-30day.json --init
python3 scripts/storage_audit.py --root /实际用户配置目录/simpleHtmlWatch --state /独立维护目录/storage-30day.json
```

按文件系统分配量记录全目录及结果缓存、任务、小时汇总、日志等分类增量，阈值为 5,000,000 字节；已观测到超限后不会因后续删除文件而自动改判通过。运行满 30 天且采样覆盖足够时才输出 `within_target`，仅过了 30 天但没有足够观测会报告 `insufficient_coverage`。每日快照证明已观测的常驻增量，不证明两次采样之间的瞬时峰值。

SSH 终端仅在内存保留最多 1,000 行回滚，服务器每次最多发送一个 16 KiB 的待确认输出块；不保存本机终端记录。远端 shell 自身的历史或服务日志由远端系统管理。

采用 `completed.json.gz` 后不能直接降级到不认识该索引的旧程序，否则可能无法识别已清理的旧任务身份。维护备份须包含压缩索引。
